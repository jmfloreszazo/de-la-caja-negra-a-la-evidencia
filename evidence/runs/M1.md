# M1 · Measured gRPC/REST transport evidence

**Captured:** 29 October 2026 at 19:50 UTC, [GitHub Actions #40943584513](https://github.com/jmfloreszazo/de-la-caja-negra-a-la-evidencia/actions/runs/40943584513). GitHub checked out a temporary PR merge SHA; the snapshots preserve **both** the workflow PR head and the checkout commit.

**Scope:** identical **non-durable** decision, .NET 10 Kestrel, HTTP/2 cleartext on localhost, shared Linux runner (2 reported processors), 2,500 requests per trial, concurrency 8 and 32, warmup, order gRPC → REST → REST → gRPC. **Not** a committed banking transaction benchmark, Azure, remote branch, TLS, WAN, SQL or mainframe equivalence.

## All observed rounds (not cherry-picked)

| Concurrency | Protocol | Replies/s in two trials | p99 in two trials |
|---|---|---|---|
| 8 | gRPC / Protobuf | 7,529.93 / 7,861.87 | 3.354 / 3.726 ms |
| 8 | REST / JSON | 6,160.98 / 8,030.43 | 2.460 / 2.717 ms |
| 32 | gRPC / Protobuf | 11,575.60 / 9,299.15 | 5.973 / 8.508 ms |
| 32 | REST / JSON | 8,826.66 / 9,967.68 | 9.483 / 6.469 ms |

Each trial lasted a **fraction of a second**, with scheduling and noise from a shared CI runner. There is no consistent tail-latency advantage for gRPC: at concurrency 8 its p99 was higher in both trials, and the 32-concurrency results are mixed. Do not claim statistical superiority or extrapolate Azure cost.
