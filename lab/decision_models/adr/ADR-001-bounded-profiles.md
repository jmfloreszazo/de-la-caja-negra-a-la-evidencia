# ADR-001: Explicit bounded decision and trace profiles

- Status: proposed; synthetic demonstration only, not approved
- Version: v1
- Baseline: BASELINE-FEE-DEMO
- Capability: synthetic parsed COBOL fee capability
- Accountable owner: unassigned; repository editorial authority remains with José María Flores Zazo
- Decision date: not an approval timestamp
- Sources: SRC-FEE-CONTRACT (`examples/fee-contract.md`)
- Models: FEE-DECISION v1, FEE-PROCESS v1
- Tests: `test_toolkit.py`; independently written expectations in `examples/fee-cases.json`

## Context and forces

COBOL migration needs explicit business decisions and observable process obligations, not only legacy-output replay. Full DMN FEEL and BPMN execution would add significant dependencies, semantics and certification obligations. A small offline tool should reject unsupported constructs rather than silently approximate them. The existing protected oracle and TODM evidence adapter must remain unchanged.

## Decision

Use locally defined version-1 JSON profiles inspired by DMN decision tables (UNIQUE/FIRST) and BPMN sequential process traces. These are not OMG interchange documents or conformant engines. FIRST is selected for the fee decision so invalid-domain rules precede the inactive rule. Exact rational arithmetic parses integer/decimal-string operands and explicitly rounds once at the output boundary. UNIQUE rejects multiple matches on evaluated input, but static validation does not prove all-domain non-overlap or coverage.

Use a baseline manifest to enumerate source, ADR, model and independent case bytes with SHA256. Cross-check source/ADR links and model baseline identity. The manifest records an owner and an unverified approval claim but supplies no signature, identity verification, revocation check or authority gate. Hash consistency does not prove truth or independence. This proposal deliberately keeps productionApproved false.

## Alternatives

- A full DMN/BPMN engine: necessary for wider expressions, interchange or workflow execution; deferred rather than emulated.
- Hand-written conditionals alone: easy to execute, but less visible rule-level traceability.
- Golden master alone: detects differences, but can preserve legacy defects; retain it as a complementary compatibility check.
- SBVR, CMMN and OCL engines: not implemented. Record vocabulary, discretionary case tasks and invariants as reviewed mappings only.

## Consequences and limits

Useful for local rule/trace qualification and baseline byte binding. It cannot authorize a release, prove business correctness, validate a real COBOL parser, assert mainframe/Azure performance, establish E1-E4 completion, or automatically feed a PASS into the existing TODM gate. The source of acceptance truth is an accountable approved baseline, not this ADR or a model alone.

## Verification and change control

Run the README unit tests and CLI examples, including unique overlap, invalid transition, incomplete observations and arithmetic ties. Expected fee cases are manually curated, not generated by the evaluator or copied from protected snapshots. Changes require a new reviewed baseline/version and independently reviewed expectations; never update hashes merely to hide a mismatch. Any production baseline requires identified authority, scope, evidence of mandate, approval, expiry/revocation rules, and external release governance. This ADR makes none of those approvals.
