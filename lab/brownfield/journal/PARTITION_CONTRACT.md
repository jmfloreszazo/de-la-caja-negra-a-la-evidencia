# Directional controller-stream fault contract V1

Preregistered scope for #58: four cases, legacy/candidate crossed with client-to-server/server-to-client byte suppression. This is an opaque TCP application-stream relay that consumes and discards selected bytes while keeping sockets open. TCP acknowledges the proxy's reads; this is not kernel-level packet blackholing or a physical network partition.

An independent SQL lock barrier stops the financial adapter before COMMIT. A preconnected probe issues a tagged query after suppression starts. Independent controller observations must show existing holder sessions still alive. The tagged query reaches the server only when server-to-client bytes are suppressed. The client remains unresolved. Fresh admission and cutover attempts must fail within the fixture's connection timeout, without changing authority. The original gateway is externally killed; its adapter is left running.

Releasing the SQL barrier must allow exactly one financial decision, two postings and one outbox in the separate financial database while controller bytes are still suppressed. No outcome is inferred from the missing client response. Original controller-session states after that financial COMMIT are retained, without assuming all protocols release their locks in the same way.

Recovery explicitly closes all relay sessions before allowing fresh connections: discarded PostgreSQL protocol bytes cannot safely be replayed into an existing stream. This controlled reset is an operator/test intervention, not proof of automatic or transparent recovery. Reconciliation must find COMMITTED and identical replay must yield DUPLICATE_COMMITTED with no extra financial effect. Both persisted SQL oracles and the journal audit must pass. Copies falsely claiming no financial effect or automatic recovery must be rejected by the observation oracle; originals remain unchanged.

The canonical fixture guards, financial adapters and original oracles remain unchanged. Results retain actual PIDs, SQL wait/query observations, directional byte counters, process exit codes, command errors, both SQL snapshots, source hashes and original failures. G2 remains INCONCLUSIVE and G6 BLOCK. No real incumbent fence, business approval, external effect reconciliation, symmetric packet fault, physical HA, capacity or mainframe measurement is claimed. Later external tests must use controlled network loss, independently hosted failure domains, source-owned fencing and approved recovery targets.
